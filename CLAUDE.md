@AGENTS.md

## Проект

«doneReceived» («Сделал-получил», в интерфейсе — «Kids Tasks») — приложение на Expo 56 / React Native 0.85. Родитель создаёт задачу с наградой, ребёнок отмечает её выполненной, родитель подтверждает, и деньги попадают на баланс ребёнка. Актуальная документация продукта — отдельный репозиторий `doneReceived-obsidian` (локально — `..\doneReceived-obsidian`); каталог `obsidian-done/` в этом репозитории — устаревшая копия, он исключён из ESLint. В `canvases/` лежат макеты и вайрфреймы, они тоже исключены из линтера.

Проект работает на реальном API: главный экран (`/`) — `ParentHomePage` (дашборд родителя), а у ребёнка — `ChildHomePage` (роль просмотра `useViewerRoleStore` ставится по `kind` вошедшего аккаунта: вход, подключение устройства ребёнка, поднятая при запуске сессия); так же `/tasks` — `TasksPage` или `MyTasksPage`, `/wallet` — `WalletPage` или `ChildWalletPage`, `/rewards-history` — `RewardsHistoryPage` или `ChildRewardsHistoryPage`, `/transactions` — `TransactionsPage` или `ChildTransactionsPage` (выбор в `src/app/role-routes.tsx`), карта (`/map`, нативная MapLibre и веб-вариант) и регистрация (`/registration`) — отдельные роуты. Виджет `task-short-view` пока нигде не используется.

## Команды

Тест-раннер не настроен. Менеджер пакетов — npm, единственный lock-файл — `package-lock.json` (`yarn.lock` и `.yarnrc.yml` удалены по решению команды). Зависимости ставим через `npm ci` / `npx expo install <пакет>`; yarn не используем и второй lock-файл не создаём.

- `npm start` (`expo start`) — dev-сервер. Проект использует `expo-dev-client`, поэтому для нативного запуска нужен dev-билд, Expo Go не подойдёт (нативные модули: MapLibre, Reanimated 4, MMKV, secure-store).
- `npm run web` / `npm run ios` / `npm run android` — `ios` и `android` вызывают `expo run:*` и при первом запуске генерируют папки `ios/` и `android/`.
- `npm run lint` / `lint:fix` — `expo lint` (плоский конфиг ESLint 9: `eslint-config-expo` + Prettier как правило).
- `npm run format` / `format:check` — Prettier (одинарные кавычки, trailing commas, ширина 80).
- Проверка типов: `npx tsc --noEmit` (strict; `canvases/` и `obsidian-done/` исключены в `tsconfig.json`).
- Проверка архитектуры FSD: `npm run lint:fsd` (Steiger, конфиг в `steiger.config.ts`). Запускайте после изменений структуры `src/`.

**Данные с сервера.** Эндпоинты — в `entities/<name>/api` (через `apiRequest`), чтение — хуками React Query (`useTasks`, `useOperations`, `useWallet`, `useFeed` и др.), запись — мутациями в `features/*/model` с инвалидацией ключей. Страницы берут данные только через хуки запросов. Кто смотрит (семья, аккаунт, ребёнок) собирают хуки `features/family-tasks` (`useTaskViewer`, `useChildAccount`, `useFamilyFeed`). Актуальность данных (`shared/api/data-sync.ts`): ключи сущностей начинаются с корней `queryRoots` (это «теги»: `taskKeys.all = queryRoots.tasks`); мутация после ответа сервера вызывает `syncData(queryClient, '<что изменилось>')`, а таблица `AFFECTS` там же говорит, какие области перечитать (задание одобрено → задания, кошельки, история, лента, семья) — новое действие или связь добавляйте строкой туда, а не `invalidateQueries` вручную (свои `setQueryData` и оптимистичные обновления остаются в мутации). Перечитываются только открытые экраны, старые данные видны до прихода новых. Переход между экранами и возврат из фона перечитывают устаревшее (`app/providers/data-sync.ts`: `usePathname`, `focusManager` + `AppState`), свежими данные считаются 5 с (`staleTime`). Изменения с других устройств приходят событиями сервера по WebSocket (`shared/api/server-events.ts`, сокет `/events`, Идеи.md п. 31): пока кто-то вошёл, `useServerEvents` в `app/providers/data-sync.ts` держит сокет, тип события (`task_submitted` → `task-submitted` и т. д., таблица `SERVER_CHANGES`) уходит в тот же `syncData`; неизвестные типы пропускаются. Ping каждые 25 с, нет pong 10 с — переподключение; обрыв — переподключение с паузой 1–30 с и перечитывание всего открытого (пропущенные события сервер не досылает); `4401` / `4403` — обновление токенов тем же единственным refresh, что у запросов (`refreshAccessToken`), и снова вход. Таймеров опроса больше нет (кроме ожидания смены почты на её экране). Новое событие сервера — строка в `SERVER_CHANGES` и, если нужно, в `AFFECTS`. Запросы, которые выдают коды (POST), помечены `meta: { sync: false }` — синхронизация их не трогает.

**Семейный календарь.** Вкладка Calendar показывает текущую неделю и месяц; в развернутом месяце стрелки листают соседние месяцы. Данные — только из `GET /families/:familyId/events?from=&to=` (React Query, ключи `calendar`), диапазон не шире 92 дней: 30 дней назад и 60 вперёд для недели/героя и сетка выбранного месяца отдельным запросом. `useFamilyEvents` в `features/family-event` собирает ближайшее событие, «Ближайшие» и события для календаря; `useFamilyEvent` читает деталку по id. Создание/правка — форма в `features/family-event-form`, после ответа `syncData('calendar-changed')` перечитывает календарь; личный ответ «еду / не еду» — `features/family-event`. Сервер отдаёт `viewer.canEdit`, поэтому карандаш видят только родители; ребёнок может открыть событие и ответить. Фото, push-напоминания и отдельная аудитория в текущей версии не подключены.

**Слова дня (вкладка Languages, `/languages`).** Ребёнок учит английские слова по частотному списку, родитель вечером проверяет и платит. Всё решает сервер (п. 37 в `Идеи.md`): `GET /families/:id/children/:childId/words` — состояние ребёнка `WordsState` (включены ли, награда `rewardPoints` и плательщик `payerId` — свои у каждого ребёнка, `learnedCount` / `totalCount`, статус off / learning / review / done_today / no_funds / finished, текущая порция), `PUT …/words/settings` — родитель включает слова и меняет награду (с `timeZone` телефона; 409 `INSUFFICIENT_FUNDS` — настройки сохранены, порция ждёт денег), `POST /families/:id/task-submissions/:submissionId/words-check` — итог проверки (ответ на каждое слово). Эндпоинты и запрос `useWordsState` — `entities/word/api` (ключи `wordKeys`, корень `queryRoots.words`), мутации `useSaveWordsSettings` / `useCheckWords` / `useSubmitWords` — `features/english-words`, настройки слов меняют данные через `syncData('words-changed')`. Порцию сервер выдаёт сам (при включении и каждый день с 4:00 по времени семьи, кнопки «Выдать» нет) как обычное назначение с полем `words` (`Task.words`: `ranks` — новые слова, `reviewRanks` — пройденные для проверки, `items` — карточки целиком); по нему экраны узнают слова дня (`isWordsTask`). Награда в кошельке ребёнка помечена диапазоном `words` — по ним итоги (дни подряд, всего, заработано) и последняя оплаченная порция. Отказ с ошибками — `lastRejection.missedRanks`; статус порции сверяется с её назначением (активно с отказом — `redo`: `GET …/words` после неудачной проверки отдаёт review, п. 38). ВРЕМЕННО словарь `data/english-words/english-words.json` (2690 слов NGSL, транскрипция CMUdict, формы, сочетания, примеры Tatoeba) зашит в приложение только для просмотра всего словаря (`WordsDeckList`, `WordViewer`): эндпоинта со всем словарём нет. Состояние собирает `useWordsOverview` (`getWordsOverview`: off / learning / review / tomorrow / noFunds / finished). На устройстве (MMKV) хранятся только учёба ребёнка `words-study-v2` и флаги обучалки `words-settings-v2`; день слов для итогов — `wordsDay` (с 4:00). Ребёнок (`ChildLanguagesPage`, `WordsStudy`): при первом входе — `WordsIntro` (как всё устроено, флаг на устройстве, снова — по «?» в шапке); когда не учит — сверху коротко состояние (`WordsState compact`), ниже весь словарь `WordsDeckList` (виртуальный `FlatList`, строки одной высоты; открыт на сегодняшних словах — `deckFocus`, они выделены): тап — `WordViewer`, карточка слова поверх размытого списка без кнопок (влево-вправо — соседние слова, вверх-вниз или тап мимо — закрыть; подсказка — серые значки `swipe-horizontal` / `swipe-vertical`, как обучалка: пропадает навсегда, когда ребёнок хоть раз листнул вбок и закрыл свайпом (`useViewerHint`, MMKV `words-settings-v2`), при свайпе вверх-вниз сразу гаснет; прозрачность — у фона и карточки по отдельности: под полупрозрачным родителем `backdropFilter` в вебе не работает; пока листают, список под карточкой идёт следом — просмотренное слово первое сверху (`scrollToOffset`, строки одной высоты) и обведено; в вебе перед открытием снимается фокус — иначе модалка, закрываясь, фокусирует нажатую строку и браузер докручивает к ней список, поэтому после закрытия ничего не прыгает; динамик в строке — рядом с нажимаемой частью, не внутри: в вебе кнопка в кнопке недопустима); карточка `WordCard` (слово с транскрипцией и неправильными формами, динамик `SpeakButton` на `expo-speech` справа, над словом мелко «Ранг 1», пример с динамиком и переводом, перевод слова — цветом слова, сочетания), «Напомнить» — слово в конец очереди, «Запомнил» — выучено; очередь хранится на устройстве (MMKV `words-study-v2`, `useWordsStudy`); запомнил все — задание само уходит на проверку (`useSubmitWords`); слова не выданы, потому что у родителя не хватает денег, — «Новые слова скоро будут»; проверка не прошла — «Слова вернули на повтор» с невыученными словами, в словаре они выделены цветом «Не вспомнил» на своих местах, «Повторить слова» — те же карточки, невыученные первыми и с пометкой «Не вспомнил», запомнил все — снова на проверку. Родитель (`LanguagesPage`): карточка ребёнка `ChildWordsCard` — имя, цветная плашка состояния (учит — голубая, ждёт проверки или не хватает денег — оранжевая, сегодня проверено — зелёная, не включено), «Сегодняшние слова» (после проверки — проверенные), полоса по словарю, итоги — три одинаковые голубые плитки с внутренней тенью, как «Created» в карточке задания: число и подпись под ним, по центру (дней подряд, всего дней, заработано), строка «Награда: $N в день · Изменить» (`WordsRewardSetup` прямо в карточке, со следующей порции), «Включить английский» (тот же выбор суммы → `PUT …/settings`), при no_funds у плательщика — «Открыть кошелёк», или «Проверить слова» → `/languages?check=<id назначения>` (`WordsCheck`: колода — `ranks` + `reviewRanks` порции вперемешку, карточки по одной, перевод скрыт — ребёнок отвечает по слову на телефоне родителя, «Показать перевод», затем «Правильно» / «Неправильно», кнопка «назад» исправляет последний ответ; ошибка — серым, не красным; всё верно — «Выплатить $N», есть ошибки — «Вернуть на повтор»; оба уходят одним `words-check`, после ответа сервера — сразу назад к карточке ребёнка, промежуточных экранов нет). В списках заданий слова дня показываются строкой `WordsTaskRow`, она ведёт на Languages; в карточках заданий их нет. У родителя на вкладке Tasks — одна строка на ребёнка (`ChildWordsTaskRow`): учит, на проверке или у плательщика «Сдано · выплачено» (новые слова завтра).

**Переводы (i18n).** `i18next` + `react-i18next`, всё лежит в `src/shared/i18n`. Словари: `locales/en.ts` — основной, по нему строится тип; `locales/ru.ts` типизирован как `Dictionary`, и TypeScript требует в нём те же ключи. Разделы словаря — по экранам и виджетам, `common` — общие слова. Ключи `t()` типизированы (`i18next.d.ts`), опечатка в ключе — ошибка `tsc`. В компонентах: `const { t } = useTranslation()` из `@shared/i18n` (не из `react-i18next` напрямую), затем `t('profile.title')`. Язык при старте: выбранный пользователем (MMKV в `storage.ts`, на вебе — localStorage), иначе язык телефона (`expo-localization`), иначе `en`. Сменить язык — `setLanguage(code)`, текущий — `useLanguage()`. Инициализация синхронная: `root-layout.tsx` импортирует `@shared/i18n` до первого рендера. Пользовательские данные (названия задач, имена, тексты событий с сервера) не переводим. Переведены все экраны; новый текст сразу пишем ключом в оба словаря. Множественное число — суффиксы `_one` / `_other`, в русском ещё `_few` / `_many` (тип `Dictionary` их допускает), в `t()` ключ без суффикса и `{ count }`. Ключ из переменной — шаблонной строкой (``t(`nav.${key}`)``): TypeScript проверяет и её. Даты и время форматирует `shared/lib/date.ts` на языке интерфейса (`toLocale*` с `i18n.language`, слова «Сегодня», «5 мин назад» — из словаря); компоненты с датами перерисовываются при смене языка вместе с родителем, который вызывает `useTranslation`. `expo-localization` — нативный модуль: после установки нужен новый dev-билд.

**Стили — только `StyleSheet`.** Tailwind, NativeWind и shadcn из проекта убраны: `className` не работает (Babel и Metro его не обрабатывают), не добавляйте их обратно и не ставьте компоненты через `npx shadcn add`. Стили модулей лежат в файлах `*.styled.ts` (`export const styles = StyleSheet.create(...)`), значения берутся из палитры и шкал `src/shared/theme/theme.ts` (`theme.colors`, `theme.fonts`, `theme.fontSize`). Межбуквенный интервал — `letterSpacing: tracking(fontSize)` из `@shared/theme` (динамические метрики Inter: крупный текст плотнее, особенно помогает кириллице); стоит у каждого стиля с `fontSize`, новые стили пишем сразу с ним. Компоненты UI-кита в `src/shared/ui` держат `StyleSheet` в том же файле (как `pill-button.tsx`) и реэкспортируются из `index.ts`. Состояния наведения и нажатия делаются через функцию `style` у `Pressable`: react-native-web добавляет к `pressed` поле `hovered` (см. `Button`). Веб-специфичные свойства (`transition*`) задаются через `Platform.select` с приведением типа. `Label` построен на `@rn-primitives/label` (на вебе это настоящий `<label htmlFor>`). Доменные компоненты (например, `RewardButton`) в `shared/ui` не кладите — им место в `entities`. Большие кнопки везде одной формы: высота 48, скругление 14, текст Inter Bold 16 (`GradientButton`, `PillButton`, `CardButton`, кнопки в шторках и Log out); 44 — только маленькие кнопки в плитках (`CardButton size="md"`), 40 — `GradientButton small`. Тень у родительских — мягкая фиолетовая, у детских — голубая.

- `expo-location`, `expo-task-manager`, `@maplibre/maplibre-react-native` — нативные модули карты и фоновой геолокации: после установки или изменения плагинов нужен новый dev build. Разрешения и purpose strings — в плагинах `expo-location` и `@maplibre/maplibre-react-native` в `app.json`.
- `expo-image-picker`, `expo-image-manipulator`, `expo-file-system` — нативные модули фото (выбор, уменьшение, повторная отправка старых фото): после установки нужен новый dev-билд; тексты разрешений — в плагине `expo-image-picker` в `app.json`.
- `expo-clipboard` — нативный модуль: после его установки нужен новый dev-билд (`npm run ios` / `npm run android`).

**Виджет карты (`src/widgets/map`)** — основная карта нативная: `map.tsx` на `@maplibre/maplibre-react-native` (v11, New Architecture) с тем же `MAP_STYLE` (Protomaps/TileJSON), `Camera`, `GeoJSONSource`, `Layer` и `Marker`. Веб-версия `map.web.tsx` остаётся только временным стендом разработки (`maplibre-gl` + deck.gl) и не является MVP. `index.ts` экспортирует `./map`, `ui/map-preview`, `ui/zone-map`; Metro выбирает файл по платформе. Нативный `@maplibre/maplibre-react-native` подключён плагином в `app.json`; после изменения нативных настроек нужен новый dev build.

- На нативе базовая карта, геозоны, метки детей и превью используют один `config/map-style.ts`; порядок координат — `[lng, lat]`. Аватары берутся через `authorizedImage` с Bearer-заголовком, без токена в URL. Атрибуция OSM/Protomaps — общий `ui/map-attribution.tsx`.
- Транспорт на нативе — базовый `GeoJSONSource` + `SymbolLayer` из публичного PIKAS-потока (`useBusesSocket`), без 60-fps deck.gl и без дорожной привязки. Ошибки карты и публичного потока независимы; подписка чистится при уходе с экрана.
- Веб-стенд по-прежнему использует `model/use-map.ts`, `create-map.ts`, воркер `public/maplibre/maplibre-gl-worker.mjs` и deck.gl. Эти модули не должны попадать в нативный бандл.
- `layers/dynamic/` содержит общие GeoJSON-преобразования зон и заглушку deck.gl для веба; нативная карта берёт из них только `zonesToGeoJson`/`zoneDraftToGeoJson`.

**Фоновая геолокация (`src/features/location`)** — только детское устройство. В `model/child-location-task.ts` зарегистрирована задача верхнего уровня `expo-task-manager`, которую импортирует `@features/location` до навигации; она работает и при headless-старте. `expo-location` запускает foreground service на Android и background location на iOS; разрешения запрашиваются по действию «включить шаринг» в `LocationSharingCard`, выбор хранится в MMKV отдельно для аккаунта и семьи. Точка уходит единственным путём — `POST /families/{familyId}/children/me/location` с `recordedAt`; WebSocket `/location` только принимает `location`/`location-access`. Задача читает сессию из SecureStore (`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`), проверяет привязку к аккаунту/семье/эпохе перед каждым запросом и повтором, не хранит координаты долговременно. При выходе/смене роли/семьи задача останавливается, запрос отменяется. Существующим установкам шаринг не включается автоматически.

**Данные в реальном времени:** `src/features/location` и `src/features/buses` открывают обычные WebSocket к бэкенду (адрес `WS_URL` в `shared/config`, по умолчанию `ws://localhost:3001`, переопределяется `EXPO_PUBLIC_WS_URL`; сообщения вида `{ event, data }`). Бэкенда в этом репозитории нет. В эмуляторе Android `localhost` — это сам эмулятор (нужен `10.0.2.2`), на реальном устройстве нужен IP компьютера. `useLocationSocket` — сокет только на приём `location`/`location-access`: координаты пишет детская фоновая задача через REST `POST /families/{familyId}/children/me/location` с `recordedAt`; сокет переподключается с backoff, а при разрыве карта опирается на REST-опрос. На карту идут только дети семьи; события без `childId` и чужие дети отбрасываются. Сам `POST` сервер принимает только от ребёнка и только если точка новее сохранённой и не старше 10 минут. Доменные типы лежат в `entities/*/model`.

**Прочее:** плагин `react-native-reanimated/plugin` в `babel.config.js` должен оставаться последним; `userInterfaceStyle` зафиксирован как `light`.

**Фото людей.** Бек отдаёт `avatarUrl` у участников семьи (`GET /families/:id/members`, `GET /families/:id`), у детей (`GET /families/:id/children`) и в `GET /users/me`; в заданиях, начислениях и ленте люди приходят только id (`createdBy`, `approvedBy`, `actorId`, `childId`) — фото берём из участников или детей по id, вошедший ребёнок своё — из `useMe()` (список детей ему закрыт). Аватар читается с токеном (`authorizedImage`, `ApiImage`). Новое место с человеком — сразу с фото, `avatar: null` только когда его правда нет.
