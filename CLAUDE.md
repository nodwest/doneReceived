## Проект

«doneReceived» («Сделал-получил», в интерфейсе — «Kids Tasks») — приложение на Expo 56 / React Native 0.85. Родитель создаёт задачу с наградой, ребёнок отмечает её выполненной, родитель подтверждает, и деньги попадают на баланс ребёнка. Описание продукта лежит на русском в `obsidian-done/Сделал-получил/` (это хранилище Obsidian, оно исключено из ESLint). В `canvases/` лежат макеты и вайрфреймы, они тоже исключены из линтера.

Проект на ранней стадии: главный экран (`/`) — `ParentHomePage` (дашборд родителя), а у ребёнка — `ChildHomePage` (роль просмотра `useViewerRoleStore` ставится по `kind` вошедшего аккаунта: вход, подключение устройства ребёнка, поднятая при запуске сессия; ВРЕМЕННО родитель переключает её тоглом Child mode в профиле); так же `/tasks` — `TasksPage` или `MyTasksPage`, `/wallet` — `WalletPage` или `ChildWalletPage`, `/rewards-history` — `RewardsHistoryPage` или `ChildRewardsHistoryPage`, `/transactions` — `TransactionsPage` или `ChildTransactionsPage` (выбор в `src/app/role-routes.tsx`), карта (`/map`, веб-виджет) и регистрация (`/registration`) — отдельные роуты. Виджет `task-short-view` пока нигде не используется.

## Команды

Тест-раннер не настроен. Менеджер пакетов — npm, единственный lock-файл — `package-lock.json` (`yarn.lock` и `.yarnrc.yml` удалены по решению команды). Зависимости ставим через `npm ci` / `npx expo install <пакет>`; yarn не используем и второй lock-файл не создаём.

- `npm start` (`expo start`) — dev-сервер. Проект использует `expo-dev-client`, поэтому для нативного запуска нужен dev-билд, Expo Go не подойдёт (нативные модули: MapLibre, Reanimated 4, MMKV, secure-store).
- `npm run web` / `npm run ios` / `npm run android` — `ios` и `android` вызывают `expo run:*` и при первом запуске генерируют папки `ios/` и `android/`.
- `npm run lint` / `lint:fix` — `expo lint` (плоский конфиг ESLint 9: `eslint-config-expo` + Prettier как правило).
- `npm run format` / `format:check` — Prettier (одинарные кавычки, trailing commas, ширина 80).
- Проверка типов: `npx tsc --noEmit` (strict; `canvases/` и `obsidian-done/` исключены в `tsconfig.json`).
- Проверка архитектуры FSD: `npm run lint:fsd` (Steiger, конфиг в `steiger.config.ts`). Запускайте после изменений структуры `src/`.

Навигация: переход «вглубь» (плитки главной, чипы на карточках, профили, задачи из профиля) — `router.push`, «назад» — `router.back()`, а если истории нет (открыли по ссылке) — на главную. Вкладки навбара переключаются через `router.dismissTo`: если вкладка уже в истории (Family → Tasks → Family), стек откатывается к ней, иначе она заменяет текущий экран; тап по подсвеченной вкладке на вложенном экране так же возвращает к её корню. Профили ребёнка и родителя собраны из одних частей: `profile-header`, `HomeSummary`, `DaySummary`, `ScreenSection`, `MapPreview`.

**Моки.** Пока нет бэкенда, данные для отрисовки берём из моков в `src/shared/mocks/` (один файл на предметную область: `parent.ts`, `summary.ts`, `activity.ts`, `tasks.ts`, `operations.ts`, `wallet.ts` (`walletMock`: баланс для моковой истории транзакций и операции с картой; `childWithdrawalsMock` — выводы детей; выплаты и награды берутся из `operationsMock`), `operations.ts` у начисленных наград хранит ещё описание задания, когда оно сдано и фото, `wishlist.ts` (`wishesMock` — вишлист Emma), `devices.ts` (`devicesMock` — по два устройства у Emma и Liam, `connectCodesMock` — коды подключения для них), `family.ts` (`childProfilesMock` и `parentProfilesMock`: баланс или выплаченное, статус «дома», координаты; `inviteCodesMock`; `familyInvitesMock` — коды, которые знает «сервер»: наши (семья Miller) и чужой семьи Johnson; счётчики задач считаются по задачам, а не хранятся), `parent.ts` (`parentMock` — вошедший родитель, `coParentMock` — второй); у каждого человека в моках есть `role` (`'parent'` у родителей, `'child'` у детей в `children.ts`), в типах `Child` и `ParentProfile` она тоже есть (даты — «дней назад» от сегодня), всё реэкспортируется через `index.ts`; картинки — в `mocks/images/`). При вёрстке нового экрана или виджета создавайте там недостающие моки, если реальных данных нет. Моки лежат в `shared`, поэтому не импортируют типы из `entities`: используйте `as const` и структурную совместимость, а типы данных объявляйте в `entities/*/model`. Страница берёт моки из `@shared/mocks` и передаёт их в виджеты через props; сами виджеты моки не импортируют. Когда появится API, заменяем только источник данных на странице.

**Данные с «сервера» (задачи).** Для сущностей, которые придут с бэкенда, данные идут как с настоящим API: эндпоинты в `entities/<name>/api`, чтение через React Query (`useTasks`), запись через мутации в `features/*/model` с инвалидацией ключей. Пока бэкенда нет, эндпоинты ходят в `entities/task/api/mock-server.ts`: он хранит задачи в памяти (стартовые данные из `tasksMock`, живут до перезапуска). С API меняются только тела функций в `tasks-api.ts`, а `mock-server.ts` удаляется. Страницы берут такие данные через хук запроса, а не напрямую из моков.

**Переводы (i18n).** `i18next` + `react-i18next`, всё лежит в `src/shared/i18n`. Словари: `locales/en.ts` — основной, по нему строится тип; `locales/ru.ts` типизирован как `Dictionary`, и TypeScript требует в нём те же ключи. Разделы словаря — по экранам и виджетам, `common` — общие слова. Ключи `t()` типизированы (`i18next.d.ts`), опечатка в ключе — ошибка `tsc`. В компонентах: `const { t } = useTranslation()` из `@shared/i18n` (не из `react-i18next` напрямую), затем `t('profile.title')`. Язык при старте: выбранный пользователем (MMKV в `storage.ts`, на вебе — localStorage), иначе язык телефона (`expo-localization`), иначе `en`. Сменить язык — `setLanguage(code)`, текущий — `useLanguage()`. Инициализация синхронная: `root-layout.tsx` импортирует `@shared/i18n` до первого рендера. Пользовательские данные (названия задач, имена, тексты событий из моков) не переводим. Переведены все экраны; новый текст сразу пишем ключом в оба словаря. Множественное число — суффиксы `_one` / `_other`, в русском ещё `_few` / `_many` (тип `Dictionary` их допускает), в `t()` ключ без суффикса и `{ count }`. Ключ из переменной — шаблонной строкой (``t(`nav.${key}`)``): TypeScript проверяет и её. Даты и время форматирует `shared/lib/date.ts` на языке интерфейса (`toLocale*` с `i18n.language`, слова «Сегодня», «5 мин назад» — из словаря); компоненты с датами перерисовываются при смене языка вместе с родителем, который вызывает `useTranslation`. `expo-localization` — нативный модуль: после установки нужен новый dev-билд.

**Стили — только `StyleSheet`.** Tailwind, NativeWind и shadcn из проекта убраны: `className` не работает (Babel и Metro его не обрабатывают), не добавляйте их обратно и не ставьте компоненты через `npx shadcn add`. Стили модулей лежат в файлах `*.styled.ts` (`export const styles = StyleSheet.create(...)`), значения берутся из палитры и шкал `src/shared/theme/theme.ts` (`theme.colors`, `theme.fonts`, `theme.fontSize`). Межбуквенный интервал — `letterSpacing: tracking(fontSize)` из `@shared/theme` (динамические метрики Inter: крупный текст плотнее, особенно помогает кириллице); стоит у каждого стиля с `fontSize`, новые стили пишем сразу с ним. Компоненты UI-кита в `src/shared/ui` держат `StyleSheet` в том же файле (как `pill-button.tsx`) и реэкспортируются из `index.ts`. Состояния наведения и нажатия делаются через функцию `style` у `Pressable`: react-native-web добавляет к `pressed` поле `hovered` (см. `Button`). Веб-специфичные свойства (`transition*`) задаются через `Platform.select` с приведением типа. `Label` построен на `@rn-primitives/label` (на вебе это настоящий `<label htmlFor>`). Доменные компоненты (например, `RewardButton`) в `shared/ui` не кладите — им место в `entities`.

**Зависимости, о которых стоит знать:**

- `expo-clipboard` — нативный модуль: после его установки нужен новый dev-билд (`npm run ios` / `npm run android`).
- `@tanstack/react-query` подключён (задачи, операции, коды приглашения), `react-native-mmkv` хранит выбранный язык (`shared/i18n/storage.ts`); `zustand` и `expo-secure-store` установлены, но пока не подключены.
- `babel-preset-expo` имеет версию `^57`, а `expo` — `~56`. Учитывайте это, если появятся ошибки Babel или Metro.

**Виджет карты (`src/widgets/map`)** — карта есть только в вебе (`map.web.tsx`, DOM-версия `maplibre-gl`). `index.ts` экспортирует `./map` и `./ui/map-preview`: на iOS и Android Metro берёт `map.tsx` и `ui/mini-map.tsx` — заглушки без MapLibre, поэтому в нативный бандл библиотека не попадает. `MapPreview` (превью в профиле, высота 180) в вебе рисует неподвижную мини-карту (`ui/mini-map.web.tsx`), без WebGL2 остаётся фон-заглушка. Карта создаётся через `model/create-map.ts` (воркер + `MAP_STYLE`), общий для большой карты и превью. Нативный `@maplibre/maplibre-react-native` установлен, но не используется и больше не указан в плагинах `app.json` (там остался только `expo-secure-store`).

- `model/use-map.ts` создаёт карту MapLibre GL и подключает оверлей deck.gl `MapboxOverlay`; возвращает `mapRef` и `deckOverlayRef`. Воркер раздаётся из `public/maplibre/maplibre-gl-worker.mjs` (`setWorkerUrl('/maplibre/...')`), его версия должна совпадать с закреплённой `maplibre-gl` 6.10.0.
- `config/map-style.ts` собирает стиль из тематических модулей в `layers/` (base, land, water, buildings, roads, places, poi), каждый из которых реэкспортируется через `index.ts`.
- `layers/dynamic/` отвечает за живые данные: позиции пользователей идут через GeoJSON-источник `users`, который обновляет `updateUserLocation`; транспорт рисуется слоем deck.gl (`createVehiclesLayer`) и передаётся через `deckOverlayRef.setProps`.

**Данные в реальном времени:** `src/features/location` и `src/features/buses` открывают обычные WebSocket к локальному бэкенду (адрес `WS_URL` в `shared/config`, по умолчанию `ws://localhost:3001`, переопределяется `EXPO_PUBLIC_WS_URL`; сообщения вида `{ event, data }`). Бэкенда в этом репозитории нет. В эмуляторе Android `localhost` — это сам эмулятор (нужен `10.0.2.2`), на реальном устройстве нужен IP компьютера. `useLocationSocket` дополнительно запускает браузерную геолокацию и отправляет её от имени захардкоженного пользователя `user-1`. Доменные типы лежат в `entities/*/model`.

**Прочее:** плагин `react-native-reanimated/plugin` в `babel.config.js` должен оставаться последним; `userInterfaceStyle` зафиксирован как `light`.
