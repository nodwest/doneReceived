## Проект

«doneReceived» («Сделал-получил», в интерфейсе — «Kids Tasks») — приложение на Expo 56 / React Native 0.85. Родитель создаёт задачу с наградой, ребёнок отмечает её выполненной, родитель подтверждает, и деньги попадают на баланс ребёнка. Описание продукта лежит на русском в `obsidian-done/Сделал-получил/` (это хранилище Obsidian, оно исключено из ESLint). В `canvases/` лежат макеты и вайрфреймы, они тоже исключены из линтера.

Проект на ранней стадии: главный экран (`/`) — `ParentHomePage` (дашборд родителя), а у ребёнка — `ChildHomePage` (роль просмотра `useViewerRoleStore` ставится по `kind` вошедшего аккаунта: вход, подключение устройства ребёнка, поднятая при запуске сессия); так же `/tasks` — `TasksPage` или `MyTasksPage`, `/wallet` — `WalletPage` или `ChildWalletPage`, `/rewards-history` — `RewardsHistoryPage` или `ChildRewardsHistoryPage`, `/transactions` — `TransactionsPage` или `ChildTransactionsPage` (выбор в `src/app/role-routes.tsx`), карта (`/map`, веб-виджет) и регистрация (`/registration`) — отдельные роуты. Виджет `task-short-view` пока нигде не используется.

## Команды

Тест-раннер не настроен. Менеджер пакетов — npm, единственный lock-файл — `package-lock.json` (`yarn.lock` и `.yarnrc.yml` удалены по решению команды). Зависимости ставим через `npm ci` / `npx expo install <пакет>`; yarn не используем и второй lock-файл не создаём.

- `npm start` (`expo start`) — dev-сервер. Проект использует `expo-dev-client`, поэтому для нативного запуска нужен dev-билд, Expo Go не подойдёт (нативные модули: MapLibre, Reanimated 4, MMKV, secure-store).
- `npm run web` / `npm run ios` / `npm run android` — `ios` и `android` вызывают `expo run:*` и при первом запуске генерируют папки `ios/` и `android/`.
- `npm run lint` / `lint:fix` — `expo lint` (плоский конфиг ESLint 9: `eslint-config-expo` + Prettier как правило).
- `npm run format` / `format:check` — Prettier (одинарные кавычки, trailing commas, ширина 80).
- Проверка типов: `npx tsc --noEmit` (strict; `canvases/` и `obsidian-done/` исключены в `tsconfig.json`).
- Проверка архитектуры FSD: `npm run lint:fsd` (Steiger, конфиг в `steiger.config.ts`). Запускайте после изменений структуры `src/`.

**Роутинг (Expo Router).** Файлы-роуты лежат в корневой папке `app/` (не путать со слоем FSD `src/app/`): `_layout.tsx`, `index.tsx` (`/`), `tasks.tsx` (`/tasks`), `create-task.tsx` и `edit-task.tsx` (`/edit-task?id=…`, оба открываются модалкой), `map.tsx` (`/map`), `wallet.tsx` (`/wallet`) и `rewards-history.tsx` (`/rewards-history`), `transactions.tsx` (`/transactions`), `registration.tsx` (`/registration`), `child/[id]/index.tsx` (профиль ребёнка) и `child/[id]/tasks.tsx` (его задачи), `parent/[id]/index.tsx` и `parent/[id]/tasks.tsx` (профиль родителя и его задачи) и прочие табы. Это тонкие реэкспорты страниц из `src/pages/*` (`export { XPage as default } from '@pages/x'`), никакой логики в них нет. Папка роутов задана плагином в `app.json`: `["expo-router", { "root": "./app" }]`. Без этого Expo Router брал бы `src/app` (она приоритетнее корневой `app/`) и принял бы за роуты `providers/`. `main` в `package.json` — `expo-router/entry`. Новый экран: страница в `src/pages/<name>`, реэкспорт в `app/<route>.tsx`. Навигация: переход «вглубь» (плитки главной, чипы на карточках, профили, задачи из профиля) — `router.push`, «назад» — `router.back()`, а если истории нет (открыли по ссылке) — на главную. Вкладки навбара переключаются через `router.dismissTo`: если вкладка уже в истории (Family → Tasks → Family), стек откатывается к ней, иначе она заменяет текущий экран; тап по подсвеченной вкладке на вложенном экране так же возвращает к её корню. Профили ребёнка и родителя собраны из одних частей: `profile-header`, `HomeSummary`, `DaySummary`, `ScreenSection`, `MapPreview`.

Если в описаниях модулей выше ещё встречаются «моковые» дети, родители, задания или Child mode — это устаревшие места описания, ориентируйтесь на код. «Свои» задания и награды экраны узнают по id вошедшего аккаунта (`useMyId()` из `@entities/session`), имена родителей — из участников семьи, детей — из `GET /families/:id/children` или `GET /families/:id`. **Данные с сервера.** Эндпоинты — в `entities/<name>/api` (через `apiRequest`), чтение — хуками React Query (`useTasks`, `useOperations`, `useWallet`, `useFeed` и др.), запись — мутациями в `features/*/model` с инвалидацией ключей. Страницы берут данные только через хуки запросов. Кто смотрит (семья, аккаунт, ребёнок) собирают хуки `features/family-tasks` (`useTaskViewer`, `useChildAccount`, `useFamilyFeed`). Актуальность данных (`shared/api/data-sync.ts`): ключи сущностей начинаются с корней `queryRoots` (это «теги»: `taskKeys.all = queryRoots.tasks`); мутация после ответа сервера вызывает `syncData(queryClient, '<что изменилось>')`, а таблица `AFFECTS` там же говорит, какие области перечитать (задание одобрено → задания, кошельки, история, лента, семья) — новое действие или связь добавляйте строкой туда, а не `invalidateQueries` вручную (свои `setQueryData` и оптимистичные обновления остаются в мутации). Перечитываются только открытые экраны, старые данные видны до прихода новых. Переход между экранами и возврат из фона перечитывают устаревшее (`app/providers/data-sync.ts`: `usePathname`, `focusManager` + `AppState`), свежими данные считаются 5 с (`staleTime`). Изменения с других устройств пока приходят таймером `SYNC_POLL_MS` (15 с: задания, лента, кошелёк ребёнка); когда сервер начнёт слать события по WebSocket (Идеи.md п. 31), они пойдут в тот же `syncData`, а таймер уберём. Запросы, которые выдают коды (POST), помечены `meta: { sync: false }` — синхронизация их не трогает.

**Переводы (i18n).** `i18next` + `react-i18next`, всё лежит в `src/shared/i18n`. Словари: `locales/en.ts` — основной, по нему строится тип; `locales/ru.ts` типизирован как `Dictionary`, и TypeScript требует в нём те же ключи. Разделы словаря — по экранам и виджетам, `common` — общие слова. Ключи `t()` типизированы (`i18next.d.ts`), опечатка в ключе — ошибка `tsc`. В компонентах: `const { t } = useTranslation()` из `@shared/i18n` (не из `react-i18next` напрямую), затем `t('profile.title')`. Язык при старте: выбранный пользователем (MMKV в `storage.ts`, на вебе — localStorage), иначе язык телефона (`expo-localization`), иначе `en`. Сменить язык — `setLanguage(code)`, текущий — `useLanguage()`. Инициализация синхронная: `root-layout.tsx` импортирует `@shared/i18n` до первого рендера. Пользовательские данные (названия задач, имена, тексты событий из моков) не переводим. Переведены все экраны; новый текст сразу пишем ключом в оба словаря. Множественное число — суффиксы `_one` / `_other`, в русском ещё `_few` / `_many` (тип `Dictionary` их допускает), в `t()` ключ без суффикса и `{ count }`. Ключ из переменной — шаблонной строкой (``t(`nav.${key}`)``): TypeScript проверяет и её. Даты и время форматирует `shared/lib/date.ts` на языке интерфейса (`toLocale*` с `i18n.language`, слова «Сегодня», «5 мин назад» — из словаря); компоненты с датами перерисовываются при смене языка вместе с родителем, который вызывает `useTranslation`. `expo-localization` — нативный модуль: после установки нужен новый dev-билд.

**Стили — только `StyleSheet`.** Tailwind, NativeWind и shadcn из проекта убраны: `className` не работает (Babel и Metro его не обрабатывают), не добавляйте их обратно и не ставьте компоненты через `npx shadcn add`. Стили модулей лежат в файлах `*.styled.ts` (`export const styles = StyleSheet.create(...)`), значения берутся из палитры и шкал `src/shared/theme/theme.ts` (`theme.colors`, `theme.fonts`, `theme.fontSize`). Межбуквенный интервал — `letterSpacing: tracking(fontSize)` из `@shared/theme` (динамические метрики Inter: крупный текст плотнее, особенно помогает кириллице); стоит у каждого стиля с `fontSize`, новые стили пишем сразу с ним. Компоненты UI-кита в `src/shared/ui` держат `StyleSheet` в том же файле (как `pill-button.tsx`) и реэкспортируются из `index.ts`. Состояния наведения и нажатия делаются через функцию `style` у `Pressable`: react-native-web добавляет к `pressed` поле `hovered` (см. `Button`). Веб-специфичные свойства (`transition*`) задаются через `Platform.select` с приведением типа. `Label` построен на `@rn-primitives/label` (на вебе это настоящий `<label htmlFor>`). Доменные компоненты (например, `RewardButton`) в `shared/ui` не кладите — им место в `entities`. Большие кнопки везде одной формы: высота 48, скругление 14, текст Inter Bold 16 (`GradientButton`, `PillButton`, `CardButton`, кнопки в шторках и Log out); 44 — только маленькие кнопки в плитках (`CardButton size="md"`), 40 — `GradientButton small`. Тень у родительских — мягкая фиолетовая, у детских — голубая.

**Зависимости, о которых стоит знать:**

- `expo-image-picker`, `expo-image-manipulator`, `expo-file-system` — нативные модули фото (выбор, уменьшение, повторная отправка старых фото): после установки нужен новый dev-билд; тексты разрешений — в плагине `expo-image-picker` в `app.json`.
- `expo-clipboard` — нативный модуль: после его установки нужен новый dev-билд (`npm run ios` / `npm run android`).
- `@tanstack/react-query` подключён (задачи, операции, коды приглашения), `react-native-mmkv` хранит выбранный язык (`shared/i18n/storage.ts`); `zustand` и `expo-secure-store` установлены, но пока не подключены.
- `babel-preset-expo` имеет версию `^57`, а `expo` — `~56`. Учитывайте это, если появятся ошибки Babel или Metro.

**Виджет карты (`src/widgets/map`)** — карта есть только в вебе (`map.web.tsx`, DOM-версия `maplibre-gl`). `index.ts` экспортирует `./map` и `./ui/map-preview`: на iOS и Android Metro берёт `map.tsx` и `ui/mini-map.tsx` — заглушки без MapLibre, поэтому в нативный бандл библиотека не попадает. `MapPreview` (превью в профиле, высота 180) в вебе рисует неподвижную мини-карту (`ui/mini-map.web.tsx`), без WebGL2 остаётся фон-заглушка. Карта создаётся через `model/create-map.ts` (воркер + `MAP_STYLE`), общий для большой карты и превью. Нативный `@maplibre/maplibre-react-native` установлен, но не используется и больше не указан в плагинах `app.json` (там остался только `expo-secure-store`).

- `model/use-map.ts` создаёт карту MapLibre GL и подключает оверлей deck.gl `MapboxOverlay`; возвращает `mapRef` и `deckOverlayRef`. Воркер раздаётся из `public/maplibre/maplibre-gl-worker.mjs` (`setWorkerUrl('/maplibre/...')`), его версия должна совпадать с закреплённой `maplibre-gl` 6.10.0.
- `config/map-style.ts` собирает стиль из тематических модулей в `layers/` (base, land, water, buildings, roads, places, poi), каждый из которых реэкспортируется через `index.ts`.
- `layers/dynamic/` отвечает за живые данные: позиции пользователей идут через GeoJSON-источник `users`, который обновляет `updateUserLocation`; транспорт рисуется слоем deck.gl (`createVehiclesLayer`) и передаётся через `deckOverlayRef.setProps`.

**Данные в реальном времени:** `src/features/location` и `src/features/buses` открывают обычные WebSocket к локальному бэкенду (адрес `WS_URL` в `shared/config`, по умолчанию `ws://localhost:3001`, переопределяется `EXPO_PUBLIC_WS_URL`; сообщения вида `{ event, data }`). Бэкенда в этом репозитории нет. В эмуляторе Android `localhost` — это сам эмулятор (нужен `10.0.2.2`), на реальном устройстве нужен IP компьютера. `useLocationSocket` входит токеном сессии; браузерную геолокацию запускает и координаты отправляет только ребёнок (`kind: 'child'`), родитель лишь получает позиции детей; события без `childId` и чужих детей (когда дети семьи загружены) на карту не идут. Доменные типы лежат в `entities/*/model`.

**Прочее:** плагин `react-native-reanimated/plugin` в `babel.config.js` должен оставаться последним; `userInterfaceStyle` зафиксирован как `light`.

**Фото людей.** Бек отдаёт `avatarUrl` у участников семьи (`GET /families/:id/members`, `GET /families/:id`), у детей (`GET /families/:id/children`) и в `GET /users/me`; в заданиях, начислениях и ленте люди приходят только id (`createdBy`, `approvedBy`, `actorId`, `childId`) — фото берём из участников или детей по id, вошедший ребёнок своё — из `useMe()` (список детей ему закрыт). Аватар читается с токеном (`authorizedImage`, `ApiImage`). Новое место с человеком — сразу с фото, `avatar: null` только когда его правда нет.
