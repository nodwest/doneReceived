# dr-mobile-api-security

Аудит ограничен запрошенной функцией. Сначала определить, какие данные она трогает, откуда они приходят и где проходят границы доверия: устройство, сервер, другой член семьи, ребёнок без аккаунта.

## Что уже устроено в проекте

- **Сессия:**
  - лежит в `expo-secure-store`, в вебе — в `localStorage`;
  - веб только для разработки, это осознанное решение, а не находка;
  - если веб пойдёт в прод — это находка высокого уровня.
- **Обновление токенов** — одно на все одновременные 401, в `shared/api/http.ts`. Не принятый сервером refresh-токен стирает сессию.
- **Конец сессии** чистит кэш запросов (`app/providers`). Выход ещё забывает пропуск ребёнка (`useLogout`).
- **`authLog`** пишет шаги входа только в dev-сборке. Пароли и токены туда не передаются.
- **`EXPO_PUBLIC_*`** видны в собранном приложении. Секретов там быть не должно.

## Чек-лист

1. **Права на ресурс.** Клиент не должен рассчитывать на то, что сервер не заметит чужой id. Это проверка для бэкенда: отметить её в отчёте, а в клиенте не показывать чужие данные.
2. **Сессии и выход:**
   - повторное использование refresh-токена;
   - параллельные 401;
   - выход с очисткой кэша, Zustand и MMKV;
   - отзыв устройства ребёнка.
3. **Коды:**
   - коды приглашения и подключения одноразовые и с ограниченным сроком;
   - нет перебора, есть лимит попыток на сервере;
   - ошибка не раскрывает, существует ли аккаунт или семья.
4. **Хранилища.** Токены не попадают в MMKV, Zustand-persist, логи и отчёты о сбоях.
5. **Логи и ошибки.** Без токенов, координат, фото, почты и полных ответов сервера.
6. **Разрешения:**
   - камера, фото, геолокация запрашиваются в момент действия, а не на старте;
   - если пользователь отказал, есть внятный путь дальше.
7. **Deep links** не выполняют действий без подтверждения и проверки сессии.
8. **Загрузка файлов:** размер, тип, данные о месте в EXIF. Фото ребёнка не должно уходить с геометкой без необходимости.
9. **Веб:** нет XSS в отображении пользовательских данных. Для cookie-авторизации нужна защита от CSRF — сейчас её нет, мы работаем через Bearer.

## Находки

Для каждой находки: место в коде (`файл:строка`), условие, при котором её можно использовать, последствия, серьёзность, как проверить исправление. Для мобильной части сверяться с категориями [OWASP MASVS](https://mas.owasp.org/MASVS/): хранение, криптография, auth, сеть, платформа, приватность. Исправлять по одной находке и без поломки поведения.
