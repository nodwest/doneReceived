# dr-client-state

Правила проекта уже описаны в `CLAUDE.md` (разделы «Данные с «сервера»», `entities/session`, `shared/api`). Этот навык — порядок проверки, а не вторая копия правил. Если навык и `CLAUDE.md` расходятся, прав `CLAUDE.md`.

## Где что хранится

- **Данные с сервера** — только React Query. Эндпоинты лежат в `entities/<name>/api`, там же хук запроса и ключи `<name>Keys`. Мутации — в `features/*/model`.
- **Состояние интерфейса** — Zustand. Пример — роль просмотра `useViewerRoleStore`.
- **Некритичные настройки** — MMKV, например выбранный язык.
- **Сессия** — `expo-secure-store` на iOS и Android, `localStorage` в вебе. Веб нужен только для разработки, в прод он не идёт.
- **Токены и пароли** нельзя класть ни в MMKV, ни в Zustand-persist, ни в логи.

## Чек-лист

1. **Ключ запроса** содержит всё, от чего зависит ответ: id семьи, ребёнка, аккаунта. Иначе данные одного ребёнка покажутся у другого.
2. **После мутации** инвалидировать или обновить через `setQueryData` все ключи, которые она меняет. Перед тем как закончить, проверить и соседние экраны: главную, Family, профиль, Wallet.
3. **Оптимистичное обновление** делается так, как в `features/reorder-wishes`:
   - в `onMutate` вызвать `cancelQueries` и запомнить `previous`;
   - в `onError` вернуть `previous`;
   - после ответа сервера обновить данные.
4. **Повтор запроса не должен давать двойной эффект.** Мутации, которые тратят деньги или одноразовые коды (выплата, депозит, вход по коду), сами не повторяются.
5. **Обновление токена** уже сделано в `shared/api/http.ts`: при 401 одно обновление на все одновременные запросы, потом повтор. Второе обновление рядом не добавлять. Запросы, которым обновление не нужно, передают `skipRefresh`.
6. **Конец сессии** — выход или отказ сервера в refresh-токене. Кэш запросов чистит `app/providers` по подписке на `useSessionStore`. Новые данные аккаунта не должны переживать выход: в Zustand и MMKV сбрасывать их там же.
7. **Четыре состояния экрана:** загрузка, ошибка, пусто, данные. Пустое состояние не показывать, пока идёт первая загрузка. Пример — `ChildHomePage`: тело не рисуется до загрузки, иначе экран моргает.
8. **Офлайн и разрешение конфликтов** делать, только если задача этого требует.

## Проверка

`npx tsc --noEmit`, `npm run lint`, `npm run lint:fsd`. Сценарий пройти в вебе, вместе с ошибкой сервера и повтором. В ответе написать, что проверено руками, а что нет.
